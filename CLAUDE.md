# CLAUDE.md

Guidance for working in the Vormexa codebase.

## What this is

Vormexa is a **100% client-side** media toolkit (video, photo, audio, PDF). There
is **no backend** — every file is processed in the browser. Never introduce a
server upload or a third-party API that receives user file data; the entire value
proposition is privacy/offline.

## Commands

- `pnpm dev` — dev server
- `pnpm build` — `tsc -b && vite build` (must pass before committing)
- `pnpm typecheck` — `tsc -b` only
- `pnpm lint` — ESLint (flat config, `--max-warnings 0`)
- `pnpm format` / `pnpm format:check` — Prettier
- `pnpm test` — Vitest unit + integration tests (jsdom)
- `pnpm test:e2e` — Playwright end-to-end (run `pnpm exec playwright install chromium` once)
- `pnpm check` — typecheck + lint + test + build (run before pushing)
- `pnpm preview` — serve the production build with COOP/COEP headers

## Testing

- Unit/integration tests live next to their subject as `*.test.ts(x)` and run in
  jsdom. Keep pure logic in dependency-free modules (e.g. `lib/gate.ts`,
  `lib/pdf-ranges.ts`) so it's testable without loading ffmpeg/pdf.js.
- Canvas/ffmpeg/pdf pipelines that can't run in jsdom are covered by Playwright
  (`e2e/`), which drives the real production build in a headless browser.
- `src/test/setup.ts` wires jest-dom matchers and polyfills `Blob.arrayBuffer`.

## Architecture

- **Engines** live in `src/lib/` and are framework-free (no React). They return
  `Blob`s. `ffmpeg.ts` is a shared singleton — only run one ffmpeg job at a time.
- **Tools** are React components in `src/components/tools/{video,image,audio,pdf}-tools.tsx`.
  Each wraps the shared `ToolFrame`, passing `controls`, an async `action`, and a
  `renderResult`. `ToolFrame` owns files, progress, cancel, errors and results.
- **Registry**: `src/tools/registry-meta.ts` holds metadata only (light, safe to
  import anywhere for nav). `src/tools/lazy.tsx` maps each tool key to a
  `React.lazy` component so engine deps code-split per category. Keep these two in
  sync when adding a tool, and never import the tool components eagerly from nav.

## Adding a tool

1. Add metadata to `TOOLS` in `registry-meta.ts` (a unique `category/slug`).
2. Add the component in the matching `*-tools.tsx`.
3. Register it in `lazy.tsx`.

## Gotchas

- ffmpeg's multi-thread core needs cross-origin isolation (COOP/COEP). The engine
  falls back to single-thread automatically; keep the headers in `vite.config.ts`,
  `vercel.json` and `public/_headers`.
- `public/ffmpeg/*` (the ~65 MB wasm core) is gitignored and regenerated by
  `postinstall` (`scripts/copy-ffmpeg-core.mjs`). Don't commit it.
- Blob sources from ffmpeg may be backed by `SharedArrayBuffer`; copy into a fresh
  `Uint8Array`/`ArrayBuffer` before constructing a `Blob`/`DataView` (see helpers).
- Keep fonts/assets self-hosted — no external network requests.
